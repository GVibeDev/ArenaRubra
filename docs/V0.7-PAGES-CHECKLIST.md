# Arena Rubra Pages — V0.7 validation checklist

## Before push
- [ ] Patch is applied to `GVibeDev/ArenaRubra`, not to the portfolio repository.
- [ ] `Settings → Pages → Source` is set to `GitHub Actions`.
- [ ] No gameplay/source file was replaced by this patch.

## Workflow
- [ ] `Deploy Arena Rubra to GitHub Pages` starts after push to `main`.
- [ ] Checkout succeeds.
- [ ] Configure Pages succeeds.
- [ ] `Stage browser runtime` succeeds.
- [ ] The staged runtime contains `index.html`, `assets/`, `css/`, `data/` and `src/`.
- [ ] Artifact upload succeeds.
- [ ] Deployment finishes green.

## Public runtime
- [ ] `https://gvibedev.github.io/ArenaRubra/` opens.
- [ ] Intro branding images load.
- [ ] CSS loads correctly.
- [ ] Main menu opens.
- [ ] Audio failure/autoplay restrictions do not block navigation.
- [ ] A new match can be started.
- [ ] At least one tutorial opens.
- [ ] Cards and token art resolve under the project subpath.
- [ ] Map assets resolve under the project subpath.
- [ ] Browser storage can be written and survives a page reload.
- [ ] DevTools Network shows no systematic 404s for `/assets`, `/css`, `/data` or `/src`.

## Device check
- [ ] Desktop Chromium-based browser tested.
- [ ] Narrow/mobile-sized viewport tested.
- [ ] Touch interactions spot-checked on an actual phone if available.

## Portfolio gate
Only after the public runtime passes these checks should the GVibeDev.cc V0.7 site patch be applied, because that patch exposes the `Launch App` link publicly.
