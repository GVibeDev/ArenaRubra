## Extracted boundary

Deterministic Advanced AI strategic-status composition now has one canonical owner in `src/ai/strategic_status.js`.

The factory `createAiStrategicStatusService()` exposes the single `compose(input)` operation. It owns:

- proportional Pressure qualification, warning and emergency flags;
- zero-PS, HQ-defence, round-limit and all-in signals;
- midgame posture and enemy Pressure-plan interpretation;
- QG raider, immediate occupation/move, strong-sequence and prepared-sequence signals;
- Pressure-close, QG-close and faction-limited finalization-stall decisions;
- the ordered legacy mode selection;
- assembly of the historical Strategic Status result shape.

The service receives one prepared read model and does not read global game state.

## Legacy orchestration retained

`src/ai.js` retains the global `strategicStatus(player, options)` facade. It still performs, in order:

1. battlefield, HQ, central-PS and Pressure snapshot queries;
2. broader strategic-state assessment;
3. `botUpdateFinalizationMemoryF9T0(player)` exactly once;
4. Nexus and Agathoi maturity evaluation exactly once;
5. delegation to the deterministic composer;
6. `botBuildGarrisonPlanF9T0(player, result)` exactly once;
7. attachment of `garrisonPlan` to the returned status.

Memory advancement and garrison policy therefore remain outside the extracted boundary. Existing scoring, movement, purchase, tactic and action callers continue through the same `strategicStatus` global.

The returned service API is frozen. The composed result intentionally remains mutable until the legacy facade attaches `garrisonPlan`, preserving the historical object shape and sequencing.

## Explicit inputs

The composer receives:

- player/enemy identity and proportional Pressure profile;
- PS and Pressure totals;
- HQ, unit, central-cell and threat snapshots;
- central-control results;
- broader strategic posture;
- already observed finalization memory and faction maturities;
- turn and faction;
- read-only coordinate, distance, movement-range and reachable-cell functions.

`options.movesFor` remains authoritative when supplied. The historical unit-type movement-range fallback remains in the facade port.

The boundary contains no DOM, browser storage, IndexedDB, direct `window`, global `state`, telemetry, RNG, memory mutation, garrison planning or action execution.

## Loading and compatibility

`index.html` loads the AI scripts as ordinary classic scripts in this order:

```text
src/ai/pressure_perception.js
  -> src/ai/strategic_status.js
  -> src/ai.js
```

The service performs no construction-time reads, so the later loading of `state.js`, Rules and gameplay functions remains valid. Direct VM harnesses that invoke Strategic Status now prepend both AI services; tests that stub Strategic Status or only inspect unrelated `ai.js` source remain unchanged.
